# Лабораторная работа №1. Последовательное умножение матриц

## Задача

Написать программу на C++, которая перемножает две квадратные матрицы одинакового размера и замеряет время работы алгоритма. Также нужно посчитать общее число операций умножения-сложения.

**Что подаём на вход:** текстовый файл, в котором лежат две матрицы A и B размера N×N.

**Что получаем на выходе:** файл с матрицей C = A × B, время работы программы в микросекундах и количество выполненных операций.

## Алгоритм и реализация

Классическое перемножение матриц через три вложенных цикла. Для каждого элемента C[i][j] считаем скалярное произведение i-й строки матрицы A на j-й столбец матрицы B.

**Ключевая часть кода:**

```cpp
for (int i = 0; i < dim; i++) {
    for (int j = 0; j < dim; j++) {
        double sum = 0.0;
        for (int k = 0; k < dim; k++) {
            sum += first[i][k] * second[k][j];
            opCount++;
        }
        result[i][j] = sum;
    }
}
```

Теоретическая сложность — **O(N³)**. Время замеряем через `<chrono>` (steady_clock), точность — микросекунды.

Чтобы не создавать матрицы вручную для каждого размера, написан вспомогательный скрипт `generate.py` на Python — он генерирует случайные матрицы нужного размера.

## Тестирование и замеры

Корректность работы программы проверяется скриптом `verify.py` (Python + NumPy). Он берёт те же матрицы A и B, считает их произведение через `np.dot()` и сравнивает с результатом C++-программы.

**Результаты замеров:**

| N (размер матрицы) | Время работы, сек |
|--------------------|-------------------|
| 200                | 0.0061            |
| 400                | 0.0482            |
| 800                | 0.5914            |
| 1200               | 2.1035            |
| 1600               | 5.9821            |
| 2000               | 21.4507           |

## Итоги

1. **Программа работает верно** — результаты совпадают с эталоном, посчитанным через NumPy.

2. **Эксперимент подтверждает теорию** — сложность O(N³). При увеличении N с 800 до 1600 (в 2 раза) время выросло с ~0.59 с до ~5.98 с, то есть примерно в 10 раз. Теоретически должно быть в 8 раз, расхождение объясняется накладными расходами на маленьких размерах.

3. **Последовательный алгоритм быстро упирается в потолок** — уже на матрице 2000×2000 программа работает больше 20 секунд. Для бо́льших размеров ждать придётся неприемлемо долго.

4. **Следующий шаг** — распараллелить вычисления. В лабораторной работе №2 будет использован OpenMP для распределения нагрузки по ядрам процессора.
